GOAL OF THIS MILESTONE
  Map the domain to PostgreSQL without letting persistence concerns leak back
  into the domain. By the end, migrations apply against Neon and integration
  tests run against a real PostgreSQL in a container.

RULES THAT APPLY TO ALL THREE PRs
  - No attribute goes on a domain class. All mapping lives in
    IEntityTypeConfiguration<T> classes inside Infrastructure.
  - No EF in-memory provider. Ever. It does not enforce constraints and does
    not translate the same SQL, so it passes tests that fail in production.
  - Migrations use the DIRECT Neon connection string, not the pooled one.
  - Every PR follows the seven-step loop in BUILD-PLAN.md section 7.

PR7 — feat/persistence-dbcontext
================================================================================

STEP 1  Branch
    git switch main
    git pull
    git switch -c feat/persistence-dbcontext

STEP 2  Packages
    dotnet add src\UserManagementAPI.Infrastructure package Microsoft.EntityFrameworkCore
    dotnet add src\UserManagementAPI.Infrastructure package Npgsql.EntityFrameworkCore.PostgreSQL
    dotnet add src\UserManagementAPI.Infrastructure package EFCore.NamingConventions
    dotnet add src\UserManagementAPI.Api package Microsoft.EntityFrameworkCore.Design

STEP 3  Neon setup, done once in the browser
    Create the Neon project. Create a "dev" branch from "main".
    Copy both connection strings. The pooled host contains "-pooler"; the direct
    host does not. Both need SSL Mode=Require.

    cd src\UserManagementAPI.Api
    dotnet user-secrets init
    dotnet user-secrets set "ConnectionStrings:Default" "<pooled>"
    dotnet user-secrets set "ConnectionStrings:Migrations" "<direct>"
    cd ..\..

    Nothing here is ever committed. appsettings.json keeps empty placeholders so
    the shape of the configuration is visible without the values.

STEP 4  Files under src\UserManagementAPI.Infrastructure\Persistence\

    AppDbContext.cs
        DbSet<User>, DbSet<Role>, DbSet<Permission>.
        OnModelCreating applies all configurations from the assembly.
        UseSnakeCaseNamingConvention so C# PascalCase maps to PostgreSQL
        snake_case without naming every column by hand.

    AppDbContextFactory.cs
        IDesignTimeDbContextFactory. Reads the Migrations connection string.
        This is what makes "dotnet ef" work without starting the API.

    Configurations\UserConfiguration.cs
        Table "users". Id as the key.
        Email as an owned type mapped to a citext column with a unique index.
        PersonName owned, mapped to name_first and name_last.
        PasswordHash owned, mapped to password_hash.
        Status mapped by converting UserStatus to its int Id.
        Roles collection mapped through the backing field, not a public setter:
            builder.Metadata.FindNavigation(nameof(User.Roles))
                   .SetPropertyAccessMode(PropertyAccessMode.Field);
        Ignore DomainEvents — it is not persisted.

    Configurations\RoleConfiguration.cs
    Configurations\PermissionConfiguration.cs
    Configurations\UserRoleConfiguration.cs
        Composite key on UserId and RoleId. No navigation to Role.

STEP 5  Enable citext and create the migration
    The citext type needs an extension. Add to OnModelCreating:
        modelBuilder.HasPostgresExtension("citext");

    dotnet ef migrations add InitialSchema `
      --project src\UserManagementAPI.Infrastructure `
      --startup-project src\UserManagementAPI.Api

    Read the generated migration before applying it. If a column type or an
    index looks wrong, fix the configuration and regenerate — never hand-edit a
    migration.

STEP 6  Apply
    dotnet ef database update `
      --project src\UserManagementAPI.Infrastructure `
      --startup-project src\UserManagementAPI.Api

    If this hangs or fails intermittently, the pooled string is being used.
    Check which secret the design-time factory reads.

STEP 7  Verify, commit, push, PR, merge, clean up.

DEFINITION OF DONE
    Migration applies cleanly against Neon. No attribute was added to any domain
    class. The users table has a unique index on a citext email column.

PR8 — feat/persistence-repositories
================================================================================

STEP 1  Branch
    git switch main
    git pull
    git switch -c feat/persistence-repositories

STEP 2  Packages
    dotnet add tests\UserManagementAPI.IntegrationTests package Testcontainers.PostgreSql
    dotnet add tests\UserManagementAPI.IntegrationTests package FluentAssertions
    dotnet add tests\UserManagementAPI.IntegrationTests package Microsoft.EntityFrameworkCore.Design

STEP 3  Files under src\UserManagementAPI.Infrastructure\Persistence\

    Repositories\UserRepository.cs
    Repositories\RoleRepository.cs
        Implement the interfaces defined in Domain. Loads use Include only
        where the aggregate genuinely needs the child collection.

    Interceptors\DomainEventDispatchInterceptor.cs
        A SaveChangesInterceptor. Before the write is committed, collect
        DomainEvents from every tracked AggregateRoot, clear them, and dispatch
        each one. Dispatching before commit is what puts handlers inside the
        same transaction: if a handler throws, the original write rolls back.

    IUnitOfWork implementation on AppDbContext
        SaveChangesAsync only. It does not expose repositories.

STEP 4  DI extension
    src\UserManagementAPI.Infrastructure\DependencyInjection.cs
        AddInfrastructure(IConfiguration): registers AppDbContext with
        UseNpgsql, EnableRetryOnFailure(5, 10s), the naming convention, the
        interceptor, and both repositories. Call it from Program.cs — that call
        is the only place Api touches Infrastructure.

    Because a retrying execution strategy is enabled, any manual
    BeginTransaction must be wrapped in
    Database.CreateExecutionStrategy().ExecuteAsync(...). The transaction
    behavior in M3 PR11 does this in one place.

STEP 5  Integration test infrastructure
    tests\UserManagementAPI.IntegrationTests\
        DatabaseFixture.cs
            IAsyncLifetime. Starts a PostgreSqlContainer with the postgres:17
            image, runs Database.MigrateAsync on start, disposes on finish.
        DatabaseCollection.cs
            Collection definition so all integration tests share one container.

    Delete UnitTest1.cs from this project.

STEP 6  Tests
    A user round-trips: save, reload in a fresh context, all value objects
    materialise correctly.
    A duplicate email violates the unique index.
    Domain events are dispatched exactly once and cleared after SaveChanges.
    A throwing event handler rolls back the write.
    Enumeration converts to and from its int id.

STEP 7  Verify. The first run pulls the postgres image, so it is slow once.
    dotnet test UserManagementAPI.sln --configuration Release

STEP 8  Commit, push, PR, merge, clean up.

    CI note: integration tests need no secret, because Testcontainers provides
    the database. Docker is available on ubuntu-latest by default.

DEFINITION OF DONE
    Integration tests pass locally and in CI. The event dispatch test proves
    rollback works.

PR9 — feat/persistence-seed
================================================================================

STEP 1  Branch
    git switch main
    git pull
    git switch -c feat/persistence-seed

STEP 2  Files
    src\UserManagementAPI.Infrastructure\Persistence\Seed\DatabaseSeeder.cs
        Idempotent. Checks before inserting so it can run on every startup.
        Seeds the permission codes used in M4, an Administrator role holding
        all of them, a Member role holding the read codes, and one bootstrap
        administrator whose password comes from configuration, never a literal.

    Migration strategy
        Development and the compose stack: migrate and seed on startup.
        Production: migrations run as a deliberate step, not on startup.
        Gate it on the environment in Program.cs and record the reason in the
        PR description.

STEP 3  Wire into docker-compose
    The compose stack already starts PostgreSQL on 5433 with a healthcheck.
    The API container reads ConnectionStrings__Default from the environment, so
    it will migrate and seed against the compose database on boot.

STEP 4  Verify end to end
    docker compose up -d --build
    docker compose logs api --tail 30
    Look for the migration and seed log lines.
    Connect to the database and confirm the rows exist:
        docker compose exec db psql -U umapi -d umapi -c "\dt"
        docker compose exec db psql -U umapi -d umapi -c "select code from permissions;"
    docker compose down

STEP 5  Commit, push, PR, merge, clean up.

STEP 6  Close the milestone
    git tag -a v0.3.0 -m "M2: persistence — EF Core mapping, repositories, domain event dispatch, seeding"
    git push origin v0.3.0

DEFINITION OF DONE FOR M2
    docker compose up produces a schema-complete, seeded database.
    Migrations apply against Neon using the direct connection string.
    Domain still has zero package references.
    No secret appears anywhere in the repository.
