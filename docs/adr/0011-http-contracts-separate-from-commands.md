# 0011 — HTTP contracts kept separate from application commands

## Context

A controller receives a request body and a handler needs a command. The two are
usually the same fields, so the tempting shortcut is one type: bind the command
straight from the body and dispatch it.

That fuses two things with different owners and different lifetimes. The request
body is a public, versioned contract — once a client depends on it, it can only
grow, and a v2 has to coexist with v1. The command is internal — it changes
whenever the use case does, and nobody outside the process ever sees it. Fused,
every change to one is a change to the other: renaming a command field breaks a
client, and a client-facing rename forces a change through the handler.

## Decision

Request and response contracts live in `Api/Contracts/V1/` and are the only
types serialized to or from the wire. Commands live in Application and are
never serialized. A controller action maps the request to a command (with route
values where the command needs them), dispatches, and maps the Result to an
`IActionResult`. That is everything an action does.

The mapping is generated by Mapperly (ADR 0014), so the cost of the separation
is one partial method declaration per route.

## Consequences

Versioning becomes possible without touching the domain. M5 PR21 adds a v2 of a
contract whose shape genuinely differs; the command and the aggregate do not
move, and v1 keeps working.

Nullable annotations on a contract are not runtime guarantees at the
deserialization boundary: a missing field arrives as `null` whatever the type
says. The command validator is the one source of shape errors, so MVC's
implicit `[Required]` for non-nullable reference types is switched off — it
would answer 400 from model binding before the validator could answer 422 with
the field-level detail.

The cost is a second type per request that is mostly the same shape as the
command, and a generated mapper between them. That duplication is the point: the
two types are allowed to drift apart, and the mapper is where the drift is
absorbed.
